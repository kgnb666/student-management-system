## 阶段 8：账号安全与注册体验（对应问题 1、2、3、4、6）

```text
项目路径：D:\wkk\Student Management System

目标：补齐账号自助能力与注册闭环，具体包含 5 件事。

1. 自助修改密码（优先级最高）
   现状：学生与教师只能由管理员把密码重置为 123456，本人无法改密。
   要求：新增 `POST /api/auth/change-password`，支持三种角色；请求体包含原密码、新密码、确认新密码；
   校验原密码正确（BCrypt 校验）、新密码不少于 6 位且与原密码不同、两次输入一致；
   修改成功后把 sys_user.token_version 自增（旧 token 立即失效），并返回提示让用户重新登录。
   前端在顶部用户区增加「修改密码」入口，弹出表单；修改成功后清理本地登录态并跳转登录页。

2. 首次登录强制改密
   现状：管理员创建学生/教师时统一使用默认密码 123456。
   要求：sys_user 增加 need_change_password 标记，管理员创建账号与重置密码时置为 1，
   用户自助改密后置为 0；登录响应中返回该标记，前端登录后若为 1 则强制跳转改密页，
   在改密完成前不允许进入其他业务页面（后端对已登录但未改密的账号，除改密与登出接口外返回 403 并提示）。
   注意：不要影响自助注册并已被审核的学生（他们自己设置过密码）。

3. 注册接口频率限制
   现状：/api/auth/register 可被批量提交（虽然注册后是待审核状态，无法直接登录）。
   要求：参考现有 LoginAttemptService 的实现方式，增加注册限流（建议同一 IP 每小时不超过 5 次），
   超出后返回 429 与明确提示；保持单机内存实现并在类注释中说明该限制。

4. 待审核注册提醒
   现状：学生注册后处于待审核状态（status=2），但管理员端没有未读提示，需要人工翻学生列表。
   要求：新增待审核数量统计（可并入 `GET /api/admin/dashboard` 返回 pendingStudentCount），
   管理员首页概览增加「待审核注册」统计卡，点击可跳转到学生管理页并自动按待审核过滤；
   学生管理页的「待审核」筛选项可通过 URL 参数带入。

5. 登录失败计数的部署说明
   现状：LoginAttemptService 为单实例内存实现，重启或多实例部署后失效。
   要求：这一项只做“明确边界”而不是引入 Redis：在类注释、README 与 docs 中写清单实例语义；
   同时把该服务抽出可替换的接口（如 AttemptStore），默认实现为内存版，为后续接入 Redis 留出扩展点，
   但不要在本阶段真的引入 Redis 依赖。

约束：
- 改密与首登强制改密的判定必须在后端执行，前端只做交互引导。
- 新增接口不得破坏现有登录流程；管理员重置密码的既有行为保持不变（重置为 123456 并强制改密）。
- 数据库变更只允许追加字段，同步更新 sql/student_score.sql 并给出旧库 ALTER 语句。
```

## 阶段 9：成绩变更审计（对应问题 5）

```text
项目路径：D:\wkk\Student Management System

目标：把「只记录最后修改人」升级为可追溯的成绩变更历史。

1. 新增成绩变更日志表 `score_change_log`
   字段建议：id、score_id、course_id、student_id、operator_user_id、operator_name、operator_role、
   action（CREATE/UPDATE/DELETE/SUBMIT/UNLOCK）、before_usual_score、before_exam_score、before_final_score、
   after_usual_score、after_exam_score、after_final_score、remark、create_time。
   为 (score_id, create_time) 与 (course_id, create_time) 建立索引。

2. 写入时机
   - 成绩新增、修改、删除（管理员与教师两条路径都要覆盖）；
   - 批量保存成绩（每个发生变化的记录写一条，未变化的记录不写）；
   - 课程成绩提交锁定与管理员解锁（action=SUBMIT / UNLOCK，不关联具体 score_id）；
   - 课程名单变更导致成绩被连带删除时，action=DELETE 并写明原因。

3. 查询接口
   - 管理员：`GET /api/admin/score-logs?courseId=&studentId=&page=&size=`，分页返回，
     遵循项目已有的分页约定（不传 page 返回数组，传 page 返回 {records,total,current,size}）；
   - 教师：`GET /api/teacher/courses/{id}/score-logs`，只允许查看本人课程。

4. 前端
   - 管理员成绩管理页每行增加「变更记录」入口，用抽屉或弹窗展示该条成绩的变更流水
     （时间、操作人、操作类型、修改前后分数）；
   - 教师成绩录入页提供「本课程变更记录」查看入口。

约束：
- 日志只追加不修改；历史数据不回溯补齐（升级前已存在的成绩没有历史记录是正常的，需在页面提示）。
- 日志写入不得影响主流程事务：如果主操作回滚，日志也不应残留（同一事务内写入即可）。
- 不要改动 score 表既有字段语义，update_by/update_time 保留。
```

## 阶段 10：扩展性与性能（对应问题 7、8、9、10、11）

```text
项目路径：D:\wkk\Student Management System

目标：在不改变接口语义的前提下，解决数据量增长后会暴露的瓶颈。

1. 下拉框远程搜索
   现状：课程管理页与成绩管理页的下拉选项一次性加载全量学生/课程（getStudents({})、getCourses({})）。
   要求：改为 Element Plus 的远程搜索（filterable + remote + :remote-method），
   复用现有分页接口按关键字查询，默认只加载前 20 条；已选中项要能正确回显。
   注意保持「学生名单」弹窗的穿梭框仍能看到完整名单（该场景需要全量数据，可保留但限制为当前课程相关学生）。

2. 教师/学生列表分页
   现状：/api/teacher/scores 与 /api/student/scores 未分页。
   要求：按现有分页约定补充可选 page/size 参数（不传时保持原数组返回），
   教师成绩查询页与学生成绩页接入分页组件。

3. JWT 鉴权缓存
   现状：JwtInterceptor 每次请求都查一次 sys_user。
   要求：增加一个带过期时间（建议 30 秒以内）的本地缓存，缓存用户状态与 token_version；
   停用账号、重置密码、修改密码后要立即失效（缓存写入方主动清除对应 key），保证「立即失效」语义不回退。
   请用测试证明：改密后旧 token 仍然立即 401。

4. 前端样式按需加载
   现状：main.js 仍全量引入 element-plus/dist/index.css（约 362 kB）。
   要求：改为按组件注入样式（ElementPlusResolver 的 importStyle 开启），并确认所有页面样式正常；
   给出优化前后 CSS 体积对比。

5. ECharts 体积优化（可选）
   现状：图表 chunk 约 456 kB（gzip 153 kB）。
   要求：评估是否引入更轻量的图表方案或进一步裁剪；如收益不明显可只给出结论与数据，不做替换。

约束：
- 所有性能优化都必须给出量化对比（构建体积、接口耗时或 SQL 次数）。
- 不得为了性能牺牲已实现的安全语义（尤其是 token 立即失效）。
```
