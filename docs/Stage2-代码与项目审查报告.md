## 3. 实际修改

### 3.1 学生出生日期可清空

文件：`backend/src/main/java/com/example/score/entity/Student.java`

修改原因：编辑时清空出生日期后，MyBatis-Plus 默认不会更新 `null` 字段。

修改内容：给 `birthDate` 增加 `@TableField(updateStrategy = FieldStrategy.ALWAYS)`。

### 3.2 班级班主任可清空

文件：`backend/src/main/java/com/example/score/entity/ClassInfo.java`

修改原因：班级表单允许清空班主任，但旧值无法被置为 `null`。

修改内容：给 `headTeacherId` 增加 `@TableField(updateStrategy = FieldStrategy.ALWAYS)`。

### 3.3 README 更新

文件：`README.md`

修改原因：项目已经重命名为英文目录，原目录说明和启动说明需要同步。

修改内容：

- 目录结构改为 `Student Management System/`。
- 将启动备用说明改为通用描述。
- 增加“注意事项”小节，说明数据库导入、配置修改、默认密码和成绩计算规则。

## 4. 未修改的问题

| 问题 | 为什么不改 |
| --- | --- |
| Controller 使用实体或简单 DTO 接收参数 | 当前字段少，直接使用可读性正常，增加大量请求 DTO 没有实际收益 |
| Service 没有接口层 | 当前没有多实现需求，直接使用 Service 类更简单 |
| 没有分页 | 演示数据规模很小，原需求没有要求分页 |
| JWT 密钥和数据库密码写在配置中 | 课程作业本地运行可接受，README 已说明按本机修改 |
| MyBatis SQL 输出到控制台 | 有助于课程设计演示和排错，不影响功能 |
| 前端页面未拆分小区域组件 | 当前页面结构清楚，继续拆分会增加文件数量和维护成本 |
| 依赖分析提示部分依赖“未使用” | Spring Boot、MyBatis、JWT 运行时依赖会通过反射加载，不能按静态结果删除 |
| `spring-boot-starter-test` 当前没有测试源码 | 保留标准测试依赖，后续需要时可直接使用 |
| 当前自动化环境默认 NIO 启动受限 | JDK 的 Windows NIO Selector 环境问题，不属于项目代码；功能测试使用临时 NIO2 启动器完成，正式源码未加入特殊配置 |
