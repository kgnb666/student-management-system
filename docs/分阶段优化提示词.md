## 使用说明

- 一个阶段开一个独立任务，把该阶段的提示词整段粘贴进去执行，**不要一次把所有阶段塞给同一个任务**。
- 阶段之间有依赖：0（可选）→ 1 → 2 → 3 → 4 → 5 → 6，建议按顺序推进。
- 每阶段结束必须满足：前端 `npm run build` 通过、后端能打包、提供真实命令输出作为证据。
- 每段提示词后面都追加“通用要求”，防止执行者跳过验证或做无关重构。

## 阶段 1：安全加固

```text
项目路径：D:\wkk\Student Management System
技术栈：Spring Boot 3 + MyBatis-Plus + MySQL + JWT 后端，Vue 3 前端。

目标：修复以下安全问题，保持现有接口路径与业务语义不变。

1. JWT 失效能力
   现状：JwtInterceptor 只验签和解析 token，不回查用户状态，导致账号被停用或密码被重置后，旧 token 在有效期内（24 小时）仍可正常调用接口。
   要求：鉴权时校验 sys_user 的 status；并引入使旧 token 失效的机制（推荐方案：sys_user 增加 token_version 字段，改密码/停用时自增；若不想改表，可用带过期时间的内存缓存记录失效时间点）。
   验收：停用账号后旧 token 立即返回 401；重置密码后旧 token 立即返回 401；重新登录后新 token 正常可用。

2. 收紧开放注册
   现状：WebConfig 将 /api/auth/register 和 /api/auth/classes 完全放行，注册账号 status=1 可立即登录，等于任何人可用任意学号注册；/api/auth/classes 还会泄露全部班级信息。
   要求：注册必须校验「学号 + 姓名 + 班级」与管理员预置名册一致，或注册后 status=0 等待管理员审核激活；/api/auth/classes 改为需要登录才能访问，或仅返回 id 与 className 最小字段。不要直接删除注册功能。

3. 登录防爆破
   要求：同一用户名/IP 连续登录失败达到阈值后锁定一段时间；失败提示保持“用户名或密码错误”，不暴露账号是否存在；锁定期间返回明确但有节制的提示。

4. CORS 收紧
   现状：WebConfig 中同时开启 allowCredentials(true) 与 http://localhost:* 通配端口。
   要求：前端使用 Bearer token 而非 Cookie，请关闭 allowCredentials，并把 allowedOriginPatterns 收敛为本地开发地址 + 生产域名。

5. 配置外置
   现状：application.yml 中数据库密码与 jwt.secret 为明文并已入库 git；start.bat 写死 MYSQL_PWD=123456。
   要求：application.yml 改为 ${ENV:默认值} 占位符形式，保证本地零配置仍能启动；不要破坏 deploy 脚本已注入的环境变量（SPRING_DATASOURCE_*、JWT_SECRET）。

6. 登录页演示账号
   要求：前端登录页展示的演示账号密码改为可通过环境变量开关，生产部署时隐藏；本地开发默认保持可见。

约束：
- 不引入 Spring Security 全框架，保持轻量（可继续使用 spring-security-crypto + 现有拦截器）。
- 数据库结构如需变更，只允许追加字段，必须同步更新 sql/student_score.sql 并保证脚本可重复执行。
- 每处安全修改都要说明“原风险是什么、这样改为什么能消除”。
```

## 阶段 2：数据一致性与业务校验

```text
项目路径：D:\wkk\Student Management System

目标：消除成绩与课程名单相关的数据风险，并把含糊的报错改成明确提示。

1. 成绩更新不允许换课换人
   现状：ScoreService.update 允许覆盖 courseId 与 studentId，可能撞上 score 表唯一键 uk_course_student_score，也等于把一条成绩“搬”到另一门课。
   要求：更新时以该记录自身的课程与学生为准，忽略或显式拒绝请求中的变动，只允许修改分数。

2. 名单移除的连带影响必须可见
   现状：CourseService.assignStudents 会把被移出学生的成绩直接物理删除，前端没有任何提示。
   要求：删除前统计受影响成绩条数并返回给前端；前端保存前二次确认，例如“有 3 名学生被移出，将同时删除 3 条成绩，是否继续？”。若不采纳物理删除，可改为成绩作废/归档状态，但需说明取舍。

3. assignStudents 入参校验
   要求：对 studentIds 去重，校验学生是否存在且班级有效；异常时给出明确提示，而不是依赖数据库唯一键抛出“数据重复或已被其他记录引用”。

4. 唯一性预校验
   要求：StudentService.update 与 TeacherService.update 在修改学号/工号前先做查重（sys_user.username 与业务表编号），命中时提示“该学号已被占用”这类具体信息。

5. 引入 Bean Validation
   要求：加入 spring-boot-starter-validation，为 LoginRequest、RegisterRequest、ScoreRequest、BatchScoreRequest 等补充 @NotBlank / @NotNull / @Min / @Max 约束，Controller 加 @Valid，并把 MethodArgumentNotValidException 统一转换为现有 Result 格式（400 + 首条字段错误信息）。保留并复用 Service 中已有的业务规则校验。

6. 成绩留痕（时间允许再做）
   要求：为 score 增加修改人与最后修改时间语义，写入时记录当前登录用户，用于追溯改分。

约束：
- 不改动成绩计算公式和统计口径（及格 60、优秀 90、五档分布边界保持现状）。
- 接口路径不变；前端只做必要的交互补充，不重写页面。
```

## 阶段 3：性能优化

```text
项目路径：D:\wkk\Student Management System

目标：在功能与接口语义不变的前提下，降低首屏体积和列表查询开销。

1. 前端按需引入
   现状（实测构建产物）：main.js 全量引入 element-plus，产出 index chunk 约 1058 kB；ScoreDistributionChart.vue 使用 import * as echarts from 'echarts'，产出约 1035 kB（gzip 后各约 348 kB / 344 kB），构建有大于 500 kB 的警告。
   要求：Element Plus 改为按需引入（unplugin-vue-components + unplugin-auto-import）；ECharts 只注册实际使用的图表与组件（如 BarChart、CanvasRenderer、TooltipComponent、GridComponent）。目标：两个主 chunk 明显下降，构建不再出现大包警告。

2. 列表分页
   现状：后端列表接口一次返回全部 JOIN 结果，前端无分页组件（global.css 中已有 .pagination 样式可复用）。
   要求：为学生、教师、课程、成绩列表增加 MyBatis-Plus 分页（分页插件 + Page），保留现有查询参数并新增 page/size，响应结构向后兼容；前端各列表页接入 el-pagination，默认每页 10~20 条。

3. 统计下推 SQL
   现状：ScoreService.buildStatistics 把全量成绩拉到内存后用 stream 计算。
   要求：平均分、最高分、最低分、及格率、优秀率、五档分布改为 SQL 聚合一次查询返回，结果数值与现有实现逐条一致（保留 1 位小数，空集合返回全 0）。

4. 日志分级
   要求：mybatis-plus 的 StdOutImpl 只在开发环境开启，生产环境使用 slf4j 并降低级别，避免线上刷 SQL 日志。

约束：
- 路由级懒加载与图表懒加载保持现状，不要为了分包重写页面结构。
- 新增请求参数必须可选，旧前端不传 page/size 时行为保持兼容。
- 统计与分数结果必须与优化前完全一致。
```
